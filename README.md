# لوحة تحكم حماده للتوصيل

لوحة إدارية محلية كاملة (سيرفر + قاعدة بيانات + واجهة عربية RTL) بلا أي اعتماديات خارجية — تعمل على **Node.js المدمج فقط** (`node:sqlite` + `node:http`).

## التشغيل

1. تأكد من تثبيت Node.js (الإصدار 22.5 أو أحدث، الأفضل 24+).
2. شغّل السيرفر:
   - انقر مزدوجاً على `start.bat`، أو
   - نفّذ: `node server.js`
3. افتح المتصفح على: `http://localhost:3000`
4. الدخول الافتراضي:
   - اسم المستخدم: `admin`
   - كلمة المرور: `admin123`
   - (غيّرها من تبويب الإعدادات بعد أول دخول)

## ما تتضمنه اللوحة

- **لوحة الإحصائيات**: طلبات اليوم، اشتراكات قيد المراجعة، أصحاب توصيل متصلون، إجمالي الطلبات، الزبائن، الإيرادات الكلية واليومية، توزيع حالات الطلبات، آخر الأنشطة.
- **طلبات الاشتراك**: قائمة بطلبات أصحاب التوصيل مع الوثائق الخمس (صورة شخصية، بطاقة تعريف، بطاقة رمادية، تأمين، إيصال الدفع) ووسيلة الدفع (بنكيلي/مصرفي/السداد/بيم)، مع قبول/رفض وإنشاء حساب صاحب التوصيل تلقائياً عند القبول.
- **الطلبات**: بحث وتصفية، تغيير الحالة (جديد ← مقبول ← قيد التوصيل ← مكتمل)، إسناد لصاحب توصيل، إعادة طلب مرفوض.
- **أصحاب التوصيل**: تفعيل/إيقاف الاتصال، تفعيل/إيقاف الاشتراك، رقم اللوحة والتقييم.
- **الزبائن**: قائمة بعدد الطلبات.
- **سجل النشاط**: كل عمليات المسؤول موثقة.
- **الإعدادات**: تغيير كلمة المرور.

## بنية المشروع

```
Dashbord_Hamada/
├─ server.js        سيرفر HTTP + واجهة برمجية (API) + خدمة الملفات الثابتة
├─ db.js            إنشاء قاعدة البيانات + البذر (Seed) + التجزئة/المصادقة
├─ data/hamada.db   قاعدة SQLite المحلية (تُنشأ تلقائياً)
├─ public/          واجهة اللوحة (index.html + style.css + app.js + logo.svg)
└─ start.bat        تشغيل سريع
```

## قاعدة البيانات (SQLite)

- `admins`: المسؤولون (كلمة المرور مجزأة بـ scrypt + ملح عشوائي).
- `sessions`: رموز الجلسات (تنتهي تلقائياً بعد 12 ساعة).
- `customers`: الزبائن.
- `providers`: أصحاب التوصيل (الحالة، الاشتراك، التقييم، اللوحة).
- `subscription_requests`: طلبات الاشتراك (الوثائق كـ JSON، وسيلة الدفع، الحالة).
- `orders`: الطلبات (الحالة، الإسناد، السعر 100–250).
- `activity_log`: سجل النشاط.

## الأمان

- جميع كلمات المرور مجزأة بـ `scrypt` مع ملح عشوائي (لا تخزين نص صريح).
- رموز جلسات عشوائية 32 بايت، تنتهي بعد 12 ساعة، وتُتلف عند الخروج.
- كل نقاط `/api/` محمية (إلا تسجيل الدخول) وترجع `401` بدون رمز صالح.
- استعلامات SQL معلمة بالكامل (حماية من حقن SQL).
- كشف رفض معالجة طلب اشتراك مرتين.

## واجهة برمجية (API)

| الطريقة | المسار | الوصف |
|---|---|---|
| POST | `/api/auth/login` | دخول → رمز جلسة |
| POST | `/api/auth/logout` | خروج وإتلاف الرمز |
| GET | `/api/auth/me` | بيانات المسؤول الحالي |
| POST | `/api/auth/password` | تغيير كلمة المرور |
| GET | `/api/stats` | الإحصائيات |
| GET | `/api/orders?status=&q=&limit=` | قائمة الطلبات |
| POST | `/api/orders/status` | تغيير حالة الطلب |
| POST | `/api/orders/assign` | إسناد طلب |
| GET | `/api/subscription-requests?status=` | طلبات الاشتراك |
| POST | `/api/subscription-requests/:id/approve` | قبول وإنشاء الحساب |
| POST | `/api/subscription-requests/:id/reject` | رفض مع السبب |
| GET | `/api/providers` | أصحاب التوصيل |
| POST | `/api/providers/:id/toggle-connection` | تفعيل/إيقاف الاتصال |
| POST | `/api/providers/:id/toggle-subscription` | تفعيل/إيقاف الاشتراك |
| GET | `/api/customers` | الزبائن |
| GET | `/api/activity` | سجل النشاط |

## إعادة الضبط

احذف الملفات `data/hamada.db` (+ `-wal` و `-shm`) وأعد تشغيل السيرفر ليُعاد البذر تلقائياً ببيانات تجريبية.
